# UI 작업 규칙

- UI 오브젝트와 레이아웃은 Unity 씬 또는 프리팹에 직접 배치하여 실행 전에도 확인하고 수정할 수 있게 한다.
- 메뉴 UI를 실행 시 생성하거나 복제하지 않는다. 스크립트는 저장된 UI 참조를 사용해 상태, 텍스트, 버튼 동작을 갱신한다.
- 기존 구조, 네이밍, 포맷을 유지하고 요청과 무관한 코드는 수정하지 않는다.

# 기획 문서와 맵 작업 규칙

- 작업 전에 `CrossTheBoard/Docs`의 관련 기획 문서를 반드시 확인한다. 새로운 지시사항이나 기획 변경은 해당 문서에 함께 반영한다.
- UI 씬 배치 규칙은 맵 스트리밍에 적용하지 않는다. 맵은 `Resources/MapPatterns`의 15~50행 프리팹을 `GameplayScene/Map` 아래에 런타임 인스턴스화한다.
- 첫 패턴은 0행부터, 플레이어는 1행 중앙에서 시작한다. 최초 랜덤 패턴 세 개를 연결한다. 첫 경계 이후에는 이전·현재·다음 패턴을 유지하고 두 패턴 이상 지난 부분을 삭제하며 새 패턴을 추가한다. 동시에 활성화된 패턴은 최대 세 개다.
- 패턴에는 장애물, 추적 몬스터, 같은 행의 이동 장애물, 행 트리거, 사망 행과 징검다리를 저장한다. 코인과 특수 보상은 맵 생성 시 랜덤 배치한다. 다음 테마는 패턴 생성 시 미리 선택하며 경계 진입 때 이미 생성된 패턴을 교체하지 않는다.
- 장애물은 전진 통로를 완전히 막지 않도록 배치한다. 시작 좌표 중복, 같은 행의 순찰 범위, 인접한 두 행의 안전 칸 연결과 패턴 연결 경계를 검증한다.
- 추적 몬스터의 수명은 원본 패턴과 분리한다. 플레이어와 맨해튼 거리 7칸 이내에서 추적을 시작하고 이후 8칸 이상 떨어지면 삭제한다. 몬스터는 징검다리 행을 건너지 못한다.
- 사망 시 점수·이번 판 수집 코인 기록을 한 번 저장하고 씬에 배치된 중앙 점수 UI를 표시한 뒤 실제 시간 3초 후 메인 메뉴로 이동한다. 수집 당시 지급한 지갑 코인을 중복 지급하지 않는다.
- 정지한 장애물 또는 도착한 이동 장애물과 플레이어의 점유 좌표가 같으면 HP·피해 무적 시간과 관계없이 즉시 사망한다. 진입을 막는 지형은 다른 좌표에서 부딪히기만 하면 사망하지 않는다.
- 이동 장애물은 한 번 이동을 시작하면 도착 전 목적지를 바꾸거나 다른 이동을 시작하지 않는다. 출발·목적 칸 예약과 피격을 분리하고 이동 중에는 어느 칸에서도 피격 판정을 하지 않는다. 설정된 한 칸 이동 시간(1 / Speed)이 지나 도착하면 좌표를 확정하고 겹침을 판정한 뒤 다음 이동을 결정한다.
- 플레이어의 성공한 입력 이동 간격은 게임 시간 기준 0.3초다. 이동 시작 후 0.1초 미만의 방향키·스와이프 입력은 무시하고 그 이후 입력은 FIFO 큐에 저장해 이동 제한이 풀리면 순서대로 실행한다. 실행 시 막힌 방향은 버리고 다음 입력을 시도하며 실패한 이동과 발판 운반은 대기를 추가하지 않는다. 일시정지는 큐를 보존하고 새 입력을 받지 않으며 사망·초기화·비활성화 시 큐를 비운다. 몬스터·이동 장애물에는 도착 후 추가 대기를 넣지 않는다.
- MapManager는 씬의 Ground/Structures/Coins Tilemap 참조에 의존하지 않는다. 패턴의 Ground는 배경만 그리고 장애물·몬스터는 MapObstacle과 SpriteRenderer로 배치한다. 이미지 돌출과 점유 칸 판정을 분리한다.
- 용암 행은 발판을 자동 생성한다. 발판별 이미지 프리팹, 정지/좌우 왕복 형식과 초당 칸 수 속도를 설정한다. 플레이어·수집물은 발판과 함께 이동하며 몬스터는 용암 행을 건너지 못한다.
