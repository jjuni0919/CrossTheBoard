# 맵 패턴 제작

## 책임과 씬 구성

맵은 `Assets/Resources/MapPatterns` 아래의 MapPattern 프리팹을 통째로 `GameplayScene > Map` 아래에 인스턴스화한다. 이름 형식은 강제하지 않으며 Theme Id로 후보를 고른다. 하위 폴더도 검색하고, 자산 변경은 플레이 모드를 종료한 뒤 다음 게임부터 반영한다.

MapManager는 패턴 선택·연결·삭제, 런타임 점유 정보, 랜덤 수집물과 이동체를 관리한다. Ground·Structures·Coins 씬 오브젝트 참조는 필요 없다. Map의 자식이 비어 있어도 Player 참조와 Resources 패턴이 있으면 시작한다. Sprite Material, 기본 Stepping Stone Prefab, Coin Sprite, Reward Sprite는 표시 자산 설정이며 씬의 타일 레이어가 아니다. 발판별 프리팹이 없으면 기본 발판을 사용한다.

각 패턴의 Ground Tilemap은 배경만 그린다. 장애물·몬스터·발판·코인·보상은 SpriteRenderer 오브젝트로 표시하고 배경 Tilemap을 이동 판정용으로 복사하지 않는다. 패턴의 Bounds와 오브젝트의 점유 칸으로 이동을 판정한다. 메뉴 UI는 계속 씬/프리팹에 직접 배치한다.

## 패턴 기본 규칙

- 가로 x=-4..4, 총 9칸. 세로 y=0..Length-1, 15~50행.
- 첫 행과 마지막 행은 장애물과 용암 없는 연결 행이다.
- 루트 Grid는 사각형, Cell Size (1, 1, 1), Cell Gap (0, 0, 0)이다.
- Ground는 루트 바로 아래에 둔다. 로컬 위치/회전/크기는 기본값, Tile Anchor는 (0.5, 0.5, 0)이다.
- Ground의 9×Length 칸을 채우고 용암 행에도 바닥을 둔다.
- 장애물 루트의 로컬 위치는 (열+0.5, 행+0.5, 0)이다. 이미지는 Visual 자식에서 크기·위치·회전을 조절한다. 그림이 옆 칸으로 넘어가도 점유 칸은 바뀌지 않는다.

`Assets > Create > CrossTheBoard > Map Pattern`으로 새 프리팹을 만들거나 샘플을 복제한다. Length를 변경하면 `Resize / Fill Ground` 버튼으로 바닥을 맞춘다. 범위 안의 기존 바닥 그림은 보존한다.

## 장애물과 몬스터

패턴 안에 MapObstacle 오브젝트를 배치하고 자신 또는 자식의 SpriteRenderer에 이미지를 넣는다. 기존 샘플은 지형·가시·순찰 장애물·추적 몬스터를 각각 독립된 오브젝트로 변환했다. 기존 좌표, 색, 프리팹 GUID를 보존했다.

- 지형: Blocks Movement=true, Damage=0, Movement=None.
- 고정 가시: Blocks Movement=false, Damage>0, Movement=None.
- 굴러가는 돌: Blocks Movement=false, Damage>0, Movement=Patrol. Direction은 좌/우, Distance는 시작점에서 끝점까지 칸 수.
- 몬스터: Blocks Movement=false, Damage>0, Movement=Chase.
- Speed는 초당 칸 수다. 이동체는 칸 사이를 연속적으로 이동한다.
- Contact Radius는 이동체의 중심 접촉 반경이며 이미지 크기와 독립적이다. 고정 장애물 판정은 점유 칸을 사용한다.

이동 중 목적 칸과 출발 칸을 예약해 다른 이동체가 같은 구간을 역방향으로 진입하지 않도록 한다. 몬스터는 실제 오브젝트 위치로 접촉 피해를 판정하며 그림이 목적 칸에 도착하기 전에 목적 칸에 피해를 주지 않는다. 플레이어의 기존 피해 간격을 유지한다.

Chase는 플레이어와 맨해튼 거리 `|dx|+|dy|`가 7칸 이내면 추적을 시작한다. 먼 미래 패턴의 몬스터는 대기하고, 추적 시작 후 거리가 8칸 이상이면 삭제한다. 원본 패턴이 삭제될 때 남은 맵 위로 이동한 추적 몬스터를 Map 아래로 옮겨 추적을 유지한다. 몬스터는 징검다리를 포함한 용암 행 전체를 건너지 못한다. 경로가 없으면 대기한다. Patrol은 원본 패턴 삭제 시 함께 정리한다.

기존 TileBase를 받는 `TrySetObstacle` API는 호환성을 위해 유지하며 SpriteRenderer 오브젝트로 변환해 배치한다. 새 패턴 제작에는 Tile/DamageTile을 지정할 필요가 없다. 예전 패턴의 숨겨진 Structures/Moving Obstacles 데이터는 변환 호환용이며 Inspector의 `Convert Obstacles to Sprite Objects`로 변환할 수 있다.

## 용암과 움직이는 징검다리

MapPattern의 Lava Rows에 로컬 Row를 지정한다. 맵 생성 시 용암 배경과 Stepping Stones에 지정한 발판을 자동 생성한다. 따로 발판 타일을 칠하지 않는다. Stepping Stones가 비어 있는 예전 데이터는 지정된 열의 정지 발판으로 읽으며, 새 용암 행의 기본값은 중앙 발판이다.

각 발판에서 다음을 개별 설정한다.

- Column: 시작 열.
- Prefab: SteppingStone 컴포넌트와 SpriteRenderer가 있는 이미지 프리팹. 비우면 MapManager의 기본 발판을 사용한다.
- Movement: Stationary(정지), PingPong(좌우 왕복).
- Speed: 초당 칸 수. Direction은 -1 또는 1, Distance는 왕복 끝점까지 칸 수.
- Support Half Width: 발판 프리팹의 안전 판정 반폭. 이미지의 돌출 부분과 무관하다.

발판 위의 플레이어와 코인·특수 보상은 함께 이동한다. 움직이는 도중에도 탑승·하차할 수 있다. 탑승에 의한 가로 이동은 전진 점수를 주지 않는다. 고정 칸 트리거를 태운 발판 이동과 다른 발판·장애물·수집물의 목적 칸을 덮는 이동은 거부한다. 같은 행 발판의 이동 범위가 겹치거나 맵 밖으로 나가면 제작 검증에서 거부한다.

현재 화면의 안전 여부는 실제 발판 위치로 판단한다. 움직이는 발판이 비운 열은 용암이며, 기다렸다가 탑승해야 한다. 생성 검증은 시작 배치와 왕복 경로로 전진 통로를 확인하고, 실행 중 발판이 움직였다는 이유만으로 패턴 오류를 발생시키지 않는다. 연속 용암 행은 시작 징검다리 열이 서로 이어져야 한다. 해당 구간을 제작할 때 이동 속도·위상을 실제 플레이에서 확인한다.

`TryMoveSteppingStone(from, to)`는 같은 행 인접 칸으로 한 구간 이동하는 기존 API다. 자동 왕복은 MapManager가 호출하고 발판별 속도로 보간한다. 일시정지는 게임 시간과 발판 이동을 함께 멈춘다.

## 검증과 통로

`Validate Pattern`은 길이·테마·바닥 누락·장애물 중복·움직임/피해/속도·순찰 경로·용암/발판 범위·중복 트리거·전진 통로를 검사한다. 잘못된 패턴은 게임 시작 시에도 거부한다. 루트를 선택하고 Gizmos를 켜면 용암 행과 발판 시작 위치가 보인다.

모든 행에 안전한 칸이 있어야 한다. 플레이어는 최고 도달 행보다 한 행만 뒤로 갈 수 있으므로 각 인접한 두 행의 안전 칸을 연결한다. 장애물로 한 행을 완전히 막거나 돌아가려면 두 칸 이상 후진해야 하는 패턴은 거부한다. 연결 경계를 비워 서로 다른 프리팹이 붙어도 통로가 끊기지 않게 한다.

## 랜덤 연결과 수집물

첫 패턴은 0행, 플레이어는 중앙 (0, 1)에서 시작한다. 최초에는 현재·다음·다다음 세 패턴을 생성한다. 첫 경계 이후에는 이전·현재·다음 패턴을 유지하며 두 패턴 이상 지난 부분을 삭제한다. 활성 패턴은 최대 세 개, 배경은 최대 150행이다. 카메라 밖으로 나간 이전 패턴도 바로 삭제하지 않는다.

Repeat Weight 기본 0.15로 직전 프리팹만 가중치를 낮춘다. 테마에 후보가 세 개면 즉시 반복 확률은 약 7%이며 후보가 하나면 반복한다. Coin Seed=0은 게임별 랜덤이고 고정 값이면 같은 플레이 순서를 재현한다.

코인과 특수 보상은 생성 시 도달 가능한 안전한 빈 칸에만 랜덤 배치한다. 0·1행은 제외한다. Coin Chance 기본 0.14, Reward Chance 0.03, Reward Points 100이다. 특수 보상은 ItemScore에 더하고 지갑 코인으로 지급하지 않는다. 플레이어의 후진 범위를 지난 수집물은 값과 이미지 모두 정리하며 수집한 수집물을 다시 생성하지 않는다.

## 테마와 트리거

샘플은 meadow의 Meadow_15/25/40, volcano의 Volcano_20/35/50 여섯 개다. 테마 외형은 프리팹 Ground와 SpriteRenderer의 그림/색, Lava Color, Stepping Stone Color로 지정한다.

Row Trigger의 Next Theme Id 또는 `RequestThemeChange(themeId)`로 테마를 요청한다. 다음 경계에서 이전 패턴을 유지하고 미래 패턴을 새 테마로 교체한다. 현재 패턴 중간에서는 바꾸지 않는다. 여러 요청 중 마지막을 적용하고 현재 생성 테마를 요청하면 보류를 취소한다. 알 수 없는 테마는 오류로 거부한다.

RowTriggered의 ID는 `시작 행/프리팹 이름/작성 ID`다. 반복 프리팹도 배치별로 한 번씩 발동한다. Source 프리팹에 이벤트를 연결하지 말고 런타임 MapManager의 기존 이벤트를 구독한다. 패턴 삭제 시 트리거와 발동 기록을 정리한다.

사망 시 기존 GameplayController가 점수·이번 판 수집 코인 기록을 한 번 저장하고 MainMenuScene으로 복귀한다. 이미 지갑에 넣은 코인을 다시 지급하지 않는다.

## 검사 실행

검사는 companyName=CodexValidation인 별도 Unity 프로젝트에서 실행해 실제 사용자 저장을 보호한다.

- GameplayRegressionChecks.Run: 이동·카메라·점수·지형·피해·추적 수명·거리 경계·몬스터 용암 행 거부, 발판 이동·탑승·속도·정지·코인 운반.
- MapPatternRegressionChecks.Run: 여섯 프리팹의 새 구조, 잘못된 배치/속도 거부, 빈 Map에서 시작, 세 패턴 유지, 랜덤 보상, 테마 경계, 1,000행 스트리밍.
- CollectionRegressionChecks.Run: 코인·구매·캐릭터·업적·저장 변환·실패·사망 정산.
- 실제 플레이에서는 칸 사이 이동, 발판 탑승/하차, 카메라 밖 추적, 패턴 연결과 사망 후 메뉴 복귀를 확인한다.

2026-10-06 검증: 별도 Unity 프로젝트에서 회귀 검사 세 종류를 통과했다. 새 이미지 오브젝트 배치, 이미지 돌출, 실제 접촉 반경, 발판별 속도·왕복·탑승·일시정지·코인 운반, 1,000행 스트리밍을 확인했다. 실제 플레이 모드에서도 빈 Map에서 200행 진행, 패턴 세 개 유지, 발판의 연속 이동·왕복·탑승·하차, 사망 정산·디스크 재로드·메인 메뉴 복귀·재시작·저장 실패 시 보존을 통과했다. 검증 에디터의 Unity Search 색인 예외는 검증 코드에서만 구분하고 일시정지를 해제했으며 게임 예외는 별도로 감지했다. 사용자 에디터·실제 저장 파일과 실기기 빌드는 이 검사로 검증한 것이 아니다.
