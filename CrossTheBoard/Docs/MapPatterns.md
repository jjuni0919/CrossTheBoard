# 맵 패턴 제작

## 폴더와 기본 규칙

`Assets/Resources/MapPatterns` 아래에 MapPattern 컴포넌트가 붙은 프리팹을 저장하면 다음 게임 시작 시 자동으로 불러옵니다. 하위 폴더도 검색합니다. 실행 중 파일을 추가하는 방식은 아니며, 빌드에는 Resources의 프리팹이 포함됩니다.

- 가로: x = -4~4, 총 9칸.
- 세로: y = 0~Length-1, 15~50행.
- 첫 행과 마지막 행: 모든 칸이 안전하고 장애물이 없는 연결 행.
- Ground와 Structures: 프리팹 루트 Grid 바로 아래의 별도 Tilemap.
- Grid: 사각형, Cell Size (1, 1, 1), Cell Gap (0, 0, 0). Tilemap의 로컬 위치/회전/크기는 기본값을 유지합니다.
- Ground는 전체 9×Length 칸을 채웁니다. 용암 행에도 바닥 타일이 필요합니다.

맵은 Resources 프리팹 전체를 `GameplayScene > Map` 바로 아래에 런타임 인스턴스화합니다. 씬에는 고정 패턴을 배치하지 않습니다. UI는 별도로 씬에 직접 배치하는 규칙을 유지합니다. 공유 Ground/Structures Tilemap은 이동 판정용 데이터이며 렌더러는 끕니다. 화면은 각 패턴 인스턴스의 Tilemap과 Map의 Coins 레이어가 그립니다. 게임별 수집, 이동, 트리거 실행 상태는 원본 프리팹과 분리됩니다.

## 만드는 방법

1. 샘플 프리팹을 복제하거나 Project 메뉴의 `Assets > Create > CrossTheBoard > Map Pattern`으로 생성합니다.
2. 루트의 MapPattern에서 Length와 Theme Id를 지정합니다. 길이를 바꾸면 `Resize / Fill Ground` 버튼으로 바닥을 맞춥니다. 기존 범위의 바닥 타일은 보존합니다.
3. Tile Palette로 Ground를 칠하고 Structures에 고정 장애물을 칠합니다. 일반 Tile은 나무·돌처럼 길만 막고, DamageTile은 가시처럼 진입 시 접촉 피해를 줍니다. 코인이나 특수 보상은 프리팹에 저장하지 않습니다.
4. Lava Rows에 로컬 행 번호와 징검다리 x 좌표를 지정합니다.
5. Moving Obstacles에 시작 좌표, Tile, Movement, Step Interval을 지정합니다. Patrol은 Direction과 Distance도 설정합니다. Chase는 징검다리 행을 제외한 안전한 경로를 따라 플레이어 쪽으로 이동하며, 징검다리 행에서 시작할 수 없습니다.
6. Row Triggers에 프리팹 내에서 고유한 ID와 로컬 행 번호를 지정합니다.
7. `Validate Pattern` 버튼으로 확인하고 프리팹을 저장합니다. 씬/프리팹 뷰에서 루트를 선택하고 Gizmos를 켜면 용암·징검다리와 이동 장애물 위치/순찰 범위가 표시됩니다.

잘못된 길이, 겹치는 장애물, 막힌 경로, 중복 트리거는 게임 시작 시에도 오류로 거부됩니다. 단순히 입구에서 출구까지 길이 있는 것으로 충분하지 않습니다. 뒤로 최대 한 칸만 이동할 수 있으므로, 인접한 두 행의 안전한 칸들이 서로 연결되어야 합니다.

장애물 배치로 전진 자체가 불가능해지면 안 됩니다. 모든 행에 최소 하나의 안전한 칸이 있어야 하며, 앞뒤 행이 비어 있어도 한 행 전체를 막은 패턴은 거부합니다. 고정 장애물과 이동체의 시작 칸은 중복하지 않으며, 이동체를 포함해 인접한 두 행의 안전 칸들이 연결되어야 합니다. 좌우 순찰의 전체 범위도 고정 장애물·다른 이동체의 시작 칸·위험 칸과 겹치지 않아야 합니다. 패턴의 첫 행과 마지막 행을 비워 서로 다른 패턴을 연결해도 통로가 끊기지 않게 합니다. Meadow_15의 순찰 장애물은 로컬 7행의 -2열에서 1열까지 이동합니다.

이동체 Tile에는 피해가 양수인 DamageTile 자산을 지정합니다. Patrol은 `Assets/Gameplay/RollingRockTile.asset`, Chase는 `Assets/Gameplay/MonsterTile.asset`을 사용합니다. 타일이 누락된 패턴은 저장·게임 시작 전에 검증 오류로 거부하며 런타임에서 장애물을 삭제하거나 다른 타일로 임의 대체하지 않습니다. 이전의 `Invalid or overlapping moving obstacle` 문구는 좌표 중복 외에 타일 누락·타입·피해량·좌표·이동 설정 오류도 포함했습니다. 이제 잘못된 설정과 겹침을 별도로 알리고 실패 위치를 표시합니다. 실행 중 자산을 수정했다면 플레이 모드를 종료하고 파일 갱신 후 다시 시작하여 재확인합니다.

## 랜덤 생성

맵의 첫 행은 0행이고 플레이어는 1행 중앙 `(0, 1)`에서 시작합니다. 첫 패턴은 시작 칸이 안전한 같은 Theme Id의 프리팹 중 선택합니다. 게임 시작 시 랜덤 패턴 정확히 세 개를 연결하고, 세 패턴 전체의 장애물·행·코인·보상을 함께 준비합니다. 프리팹 로컬 좌표에 패턴 시작 행을 더해 월드 행을 계산하며 패턴 사이에 빈 행을 넣지 않습니다.

최초에는 현재 패턴과 이후 두 개를 연결합니다. 첫 경계 이후에는 이전·현재·다음 패턴을 유지합니다. 카메라 밖으로 나가도 이전 패턴 하나의 바닥·구조물·위험 행은 그대로 남기며, 두 패턴 이상 지난 부분만 비활성화하고 삭제한 뒤 끝에 새 랜덤 패턴을 붙입니다. 런타임에서 활성 패턴은 최대 세 개이고 공유 타일 데이터는 최대 150행입니다. 후진 한 칸 범위보다 지난 코인·특수 보상은 정리하며, 패턴 삭제 시 행 트리거·발동 기록도 정리합니다.

이전 패턴이 남아도 플레이어의 후진 제한은 최고 도달 행에서 한 칸입니다. 플레이어 경로 탐색은 탐색 중 최고 도달 행도 함께 추적해 이 제한을 지킵니다. 몬스터 경로에는 플레이어의 후진 제한을 적용하지 않습니다.

MapManager의 Repeat Weight 기본값은 0.15입니다. 직전 프리팹만 0.15, 다른 프리팹은 각각 1의 가중치를 사용합니다. 한 테마에 후보가 세 개일 때 즉시 반복 확률은 약 7%입니다. 후보가 하나라면 그 프리팹을 반복합니다.

패턴 생성 시 Coin Chance와 Reward Chance에 따라 도달 가능한 빈 칸에 코인과 특수 보상을 랜덤 배치합니다. 0행과 시작 행 1행에는 생성하지 않습니다. 생성 시 장애물, 용암의 위험 칸, 칸 트리거 및 서로와 겹치지 않습니다. 현재 특수 보상은 파란색 보너스 타일이며 Reward Points만큼 ItemScore를 올립니다. 기본값은 100점이고 지갑 코인으로 지급하지 않습니다. Coin Seed를 지정하면 같은 플레이 순서에서 패턴과 수집물 배치를 재현할 수 있습니다. 수집한 타일은 후진·복귀로 다시 생성되지 않습니다.

Chase 몬스터는 플레이어와 맨해튼 거리 `|dx| + |dy|`가 7칸 이내가 되면 추적을 시작합니다. 앞으로 미리 생성한 먼 몬스터는 원래 위치에서 대기합니다. 추적 시작 후 거리가 8칸 이상이면 타일과 이동 기록을 삭제하며 다시 생성하지 않습니다. 몬스터의 수명은 원본 패턴과 분리되어, 지난 원본 패턴이 삭제돼도 현재 위치의 남아 있는 패턴 위에서 추적을 계속합니다. 몬스터는 징검다리를 포함한 위험 행 전체를 건너지 못합니다. 강 건너 플레이어까지 경로가 없으면 강가에서 대기하고 거리 조건에 따라 삭제됩니다. 플레이어는 몬스터와 같은 칸에서도 징검다리로 이동할 수 있습니다.

Patrol 장애물은 지정된 한 행에서 Direction/Distance 범위만 좌우 왕복하고 원본 패턴 삭제 시 정리됩니다. 이동체는 코인·보상을 삭제하지 않으며 이동 중 수집물 위를 통과할 수 있습니다. 고정 가시·몬스터·이동 장애물의 접촉 피해에는 플레이어의 피해 간격이 적용됩니다. 용암의 징검다리 밖으로 이동하면 즉시 게임이 종료됩니다. 징검다리는 현재 지정 위치에 머물지만 `TryMoveSteppingStone`으로 같은 행의 인접 칸으로 이동시킬 수 있도록 안전 판정과 화면 갱신을 유지합니다. 자동 이동이나 플레이어를 태우는 기능은 아직 추가하지 않습니다.

이동체는 일반 지형과 달리 플레이어의 길을 막지 않습니다. 경로 탐색에서도 플레이어 경로는 이동체 칸을 통과할 수 있지만 접촉 피해 위험은 남습니다. 몬스터의 추적 경로는 다른 이동체를 피해 겹쳐 서지 않도록 합니다.

## 테마와 트리거

숲 테마 ID는 `meadow`, 화산 테마 ID는 `volcano`입니다. 새 테마는 해당 Theme Id를 가진 프리팹을 같은 폴더 아래 추가하면 됩니다. 테마 외형은 각 프리팹의 Ground 타일과 Tilemap Color, Lava Color, Stepping Stone Color로 설정합니다. 현재 씬의 Initial Theme Id는 `meadow`입니다.

테마 변경은 다음 중 하나로 요청합니다.

- Row Trigger의 Next Theme Id에 대상 테마를 지정합니다.
- 게임 코드에서 `MapManager.Instance.RequestThemeChange("volcano")`를 호출합니다.

요청은 다음 패턴 경계까지 보류하며 현재 세 프리팹을 중간에 바꾸지 않습니다. 플레이어가 경계에 진입할 때 이전 패턴 하나는 기존 테마로 유지하고, 미리 생성된 이후 패턴을 새 테마의 현재·다음 두 패턴으로 교체하며 수집물도 새로 생성합니다. 지난 패턴에서 따라온 추적 몬스터는 유지하고 교체되는 미래 패턴의 이동체는 정리합니다. CurrentThemeId와 ThemeChanged 이벤트는 그때 갱신되며, 경계를 한 칸 후퇴했다 돌아와도 다시 발동하지 않습니다. 여러 요청이 오면 마지막 요청을 적용하며 현재 생성 테마를 요청하면 보류를 취소합니다. 알 수 없는 테마는 맵을 바꾸기 전에 오류로 거부합니다.

RowTriggered 이벤트의 ID는 `배치 시작 행/프리팹 이름/작성한 ID` 형식입니다. 같은 프리팹이 반복돼도 배치별로 한 번씩 실행됩니다. 프리팹의 씬 오브젝트에 이벤트를 연결하는 대신, 런타임 맵의 RowTriggered를 구독해 실제 게임 오브젝트를 제어하세요.

## 검증

기존 GameplayRegressionChecks/CollectionRegressionChecks와 MapPatternRegressionChecks를 Unity 배치 모드로 실행합니다. 저장 검사는 회사명이 CodexValidation인 별도 임시 프로젝트에서만 실행하도록 제한되어 있습니다. 샘플 생성용 CreateSamples도 별도 검증 프로젝트에서만 실행하며, 기존 샘플 경로가 있으면 검증 후 재생성하여 저장합니다.

MapPatternRegressionChecks는 잘못된 이동체 타일·시작 칸 중복·완전히 막힌 행의 거부, 1행 중앙 시작, 초기 세 프리팹, 세 패턴 전체 수집물 생성, 이전 패턴 유지와 경계 삭제·추가, 테마 보류, 원본 프리팹 불변, 몬스터 추적·좌우 순찰, 1,000행 진행과 타일·이동체·트리거 개수 제한을 검사합니다. GameplayRegressionChecks는 원본 패턴 삭제 후 추적 유지, 거리 7·8칸 경계, 징검다리 진입·경로 탐색 거부도 검사합니다. 실제 플레이 모드에서는 첫 패턴 이후 바닥 렌더링과 사망 후 메인 메뉴 복귀를 확인합니다.

길이 제한 밖의 14·51행과 누락된 이동체 타일을 거부하는지도 검사합니다. 샘플의 Patrol/Chase 타일은 저장 후 해당 DamageTile 자산과 동일한 참조인지 확인합니다. 추적 몬스터는 장애물을 우회할 수 있으므로 직선거리가 매번 줄어드는 조건 대신 실제 안전 경로의 다음 칸으로 이동했는지를 검사합니다.
